# Artifact guide

The primary workflow runs the dynamic Lake case study and its validation analyses
on a CPU with supplied prediction banks. It independently recomputes runtime
decisions, evidence, and mission fulfillment. Neural inference and Gazebo
acquisition are separate optional workflows. The [paper-to-artifact guide](PAPER_GUIDE.md)
distinguishes this executable study from the primary multi-phase studies and
the numeric-only Depot figure sources.

## 1. Install and inspect

Use Linux and Python 3.11 or newer. From the repository root:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[dev,replay]'
python tools/artifact.py verify
```

Verification checks bundled input hashes, the experiment grid and source
provenance. It runs no missions. No network connection is needed after the Python
dependencies have been installed.

Read [the experiment definition](EXPERIMENT.md) for task and policy choices.
The [committed validation outputs](../examples/validation/README.md) can be viewed
without running an experiment.

## 2. Run a small comparison

```bash
python tools/artifact.py smoke --workers 2 --output results/artifact-smoke
```

This executes 27 reference missions: all nine policies and three deadline
schedules on one recording, network condition and battery condition. It compares
the scientific results with the reference. This is an installation check, not
the complete evaluation or an independent statistical sample.

## 3. Reproduce the bundled dynamic Lake study and validation

```bash
python tools/artifact.py full --workers 4 --output results/artifact-full
```

The `full` command covers this bundled study, not every experiment in the paper:

1. Verifies the supplied inputs and recomputes all 648 reference missions.
2. Runs contract rescoring and supported contract reruns, feasibility bounds,
   causal-execution ablations, hindsight search and witness verification, and
   the 144-setting sensitivity analysis.
3. Regenerates the validation CSV/JSON outputs and compares their scientific
   content with the committed references.

Outputs are written beneath the chosen directory. Committed reference files are
not overwritten. Use a fresh directory for every invocation and retain the
machine-readable receipt when reporting a reproduction result. A failed check
causes a nonzero exit status; partial output is not a successful reproduction.

The full run needs space for a copy of replay inputs and generated logs;
allow at least 2 GiB of free disk space. Runtime depends on CPU and worker count.
Wall-clock runtime is a reproduction cost, not a measured drone latency.

To also generate the six validation diagnostic figures:

```bash
python -m pip install -e '.[report]'
python tools/artifact.py full --workers 4 --figures --output results/artifact-with-figures
```

The numerical comparison is authoritative. Fonts, rasterization and image
metadata can vary between plotting-library versions.

The [figure-data guide](../examples/paper_figures/README.md) explains how to
verify the numbers underlying manuscript Figs. 4–6 and render alternative
visualizations. The Figure 4 data use the included Depot numeric case/frame
outputs; its full recording and inference inputs are not bundled. Figures 5
and 6 use Lake validation tables regenerated by the full command above.
The additional `fig7` is an artifact-only diagnostic for §5.4.

## Interpret the results

| Quantity | Meaning |
| --- | --- |
| 6 recordings | Three route families, two focal sectors each, on one known map |
| 72 conditions | 6 recordings × 3 deadline schedules × 2 networks × 2 battery conditions |
| 648 reference runs | 72 conditions × 9 policies |
| 48 comparison conditions per policy | Four previously known recordings outside the development subset; labeled `transfer` in files, not unseen flights |
| 144 sensitivity settings | Alternative scoring thresholds applied to the same reference execution histories |

A run succeeds only when every required mission constraint is satisfied.
Perception recall alone is not mission success. An infeasibility certificate, a
successful policy run and a hindsight witness are different kinds of evidence;
an unresolved search is not proof of infeasibility.

The survey contract and sensitivity map rescore fixed histories. They do not
show how policies would adapt to those requirements during a new execution.
Only runtime-supported contracts are used for contract-conditioned reruns.
See [the validation report](VALIDATION.md) for exact denominators and limitations.

## Additional checks and workflows

```bash
python -m pytest -q
python tools/check_release.py
```

Some regression tests require historical artifacts that are intentionally absent;
their skips are reported separately from the complete supplied replay. The
[verification record](VERIFICATION.md) describes the exact checks performed for
this package.

- [Model setup](MODELS.md): fetch pinned weights and rerun neural inference.
- [Simulation setup](SIMULATION.md): fetch attributed assets and acquire a new Gazebo recording.
- [Reproduction details](REPRODUCING.md): lower-level entrypoints and troubleshooting.

Neither optional workflow is required to regenerate the bundled dynamic Lake
replay results.
