# Reproduction details

Start with the [artifact guide](ARTIFACT.md). Run commands from the repository
root after installing `.[dev,replay]`. Python 3.11+ and a CPU are sufficient;
stored-prediction replay needs no GPU, model weights or Gazebo process.

For the exact tested dependency versions, use Python 3.12 and the optional
[tested requirements](requirements.txt):

```bash
python -m pip install -r docs/requirements.txt
python -m pip install --no-deps -e .
```

This includes tests and plotting dependencies. It does not install neural models
or Gazebo. The [environment receipt](verification_environment.json) records the
versions and verification scope.

## Supported artifact commands

```bash
python tools/artifact.py verify
python tools/artifact.py smoke --workers 2 --output results/artifact-smoke
python tools/artifact.py full --workers 4 --output results/artifact-full
```

`verify` checks the bundle and experiment provenance without execution. `smoke`
recomputes 27 reference missions. `full` recomputes all 648 dynamic Lake reference
missions and their complete validation suite, then compares generated scientific data with
the committed references. Every execution requires a new output directory.

This is the bundled dynamic Lake workflow, not a full reproduction of the
primary multi-phase Lake and Depot studies. Their available artifacts and
required additional inputs are listed in [PAPER_GUIDE.md](PAPER_GUIDE.md).

The wrapper preserves the runtime, policy definitions and validation
configuration. Its purpose is to prepare portable paths, keep generated results
separate from references and expose failures through a single command.

## What comparisons mean

Replay recomputes policy choices, deadline enforcement, modeled energy, evidence
and reports. It compares scientific result fields, excluding changed artifact
locations and provenance hashes where relocation changes them. Input hashes and
source provenance are checked separately. RGB and cached prediction arrays are
not regenerated by replay.

The only declared validation-source change is a neutral SVG identifier salt in
the figure renderer. Its old and new hashes and rationale are recorded in
[release_source_changes.json](release_source_changes.json). The comparison
accepts that specific source-hash change in the generated summary; scientific
tables, parameters and outcomes must remain unchanged.

The validation suite also checks reference-outcome parity, policy-input leakage
guards and fresh re-execution of hindsight witnesses. See
[VALIDATION.md](VALIDATION.md) for the declared variants, amendments and
limitations. Agreement verifies portability and preserved behavior; it does not
constitute new mission data or hardware calibration.

## Report arithmetic compatibility

The wrapper explicitly uses sequential addition when reducing aggregate reports,
matching the original Python 3.10 execution environment. Python 3.12 changed the
built-in floating-point sum. This compatibility rule applies only to reporting;
policy execution and scoring are unchanged, and table comparison remains strict.
The [verification record](VERIFICATION.md) documents the cross-version proof.

## Figures

To verify the supplied numerical data and render alternative visualizations:

```bash
python examples/paper_figures/verify_sources.py
python -m pip install -e '.[report]'
python examples/paper_figures/make_figures.py --output results/paper-figures
```

The [figure-data guide](../examples/paper_figures/README.md) describes the
sources and plotting. The alternative plots for Figs. 4–6 are not identical
to the final manuscript artwork. Figure 4 reduces original Depot case/frame
outputs; the Depot recording and neural-inference workflow is not included.
Figures 5–6 and the optional `fig7` diagnostic reduce Lake validation tables
that the full artifact workflow recomputes.

For the separate six validation diagnostic figures:

```bash
python -m pip install -e '.[report]'
python tools/artifact.py full --workers 4 --figures --output results/artifact-with-figures
```

The `report` extra installs plotting dependencies. Figures are generated from the
new numerical results beneath the selected output directory. Their appearance
can depend on locally available fonts; CSV/JSON comparisons establish numerical
agreement.

## Lower-level replay

The original replay entrypoint remains available for focused checks:

```bash
python tools/replay.py --verify-only
python tools/replay.py --output results/replay-smoke
python tools/replay.py --all --workers 4 --output results/replay-full
```

This produces `rows.json`, per-mission logs and `validation.json`. It does not
run the additional validation experiments. Input copies and logs require
approximately 1 GiB for the reference replay; allow at least 2 GiB for a complete
full artifact run.

The individual validation stages remain available through
`python -m experiments.validation.study --help`. Their historical defaults use
`results/replay-full` as the prepared data root and write analysis tables to
`examples/validation`; use the artifact wrapper for an isolated reproduction
that preserves committed reference tables.

## Tests and packaging

```bash
python -m pytest -q
python tools/check_release.py
```

Tests cover contracts, paid execution, deadline changes, routing, validation
analysis and data integrity. Historical-artifact tests can skip when their old
result trees are absent; they do not replace the complete release replay.

The release checker audits local documentation links, package metadata, file
sizes and machine-specific paths. Optional checks can be configured for
additional release constraints.

If an unrelated ROS/Python installation or globally installed pytest plugin is
injected into the shell, use a clean shell or run:

```bash
env -u PYTHONPATH -u PYTHONHOME PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest -q
```

This avoids loading unrelated host plugins; it does not change benchmark code
or require installing ROS dependencies.
